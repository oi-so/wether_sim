# 公開済み予報の選択と将来時刻の扱い

2026-09-08修正。WRF/WPSは再実行していない。

## 修正した問題

9月8日08〜16時JST、spin-up 6時間では、入力範囲が00〜18時JSTへ丸められる。旧処理は、最初のMSM予報が15時で切れた後、18時初期値を要求していた。15:52時点では未来の初期値なので404になる。

新処理は現在UTCを初期時刻の上限とし、既存サイクルを再利用できなければ、対象時刻を予報できる過去サイクルを新しい順に探す。15時初期値が未公開で12時初期値が公開済みなら、18時の入力には12時初期値の6時間予報を使う。未来の有効時刻と未来の初期時刻を区別する。

## 公開確認と未来開始

- MSMは気圧面・地表面の両ファイル、GFSは対象の予報時間のGRIB2と索引をHTTP HEADで確認する。非空のローカル保存ファイルも再利用する。
- 同じURLの確認は計画内で再利用。404は未公開/欠落として古い候補へ進む。接続失敗・認証エラー・503等は「存在しない」と取り違えずエラーを報告する。macOSの証明書エラーにはcurlのシステム信頼ストアでHEADを試す。TLS検証は維持する。
- MSM/GFSの全必要時刻の選択を終えてから気象入力本体・地理データを準備する。本体取得の404も繰り返し再試行しない。通信の一時的失敗への再試行は維持。
- **開始時刻が未来でも、公開済み予報がspin-upと丸めた終了境界まで届けば許容する。** 届かなければ、期間短縮または公開待ちを案内する。時刻変更、外挿、同じ境界場の繰り返しはしない。
- 本実装が読むMSMファイルはFH00〜15、GFSは最大120時間。このMSMの15時間制限は製品全体ではなく、本実装の対応ファイル範囲。公開遅延があるので実際に届く先はさらに短いことがある。
- 選択結果はログとケース内 `forecast_sources.json` に、有効時刻・初期時刻・予報時間・選択時刻を保存。過去事例は従来サイクルを利用可能な限り維持する。切替による境界場の差は比較実験で記録も確認する。

HEAD後に配信状態が変わる可能性はあり、本取得・GRIB抽出・物理入力検査も維持する。HEADや非空チェックだけでGRIB内容の完全性を保証するものではない。将来予報の観測比較は、観測が揃ってから実施する。

## 検証

今回の15:52事例、全期間が未来、範囲外、未公開、MSM片側だけ公開、GFS予報時間別公開、ローカルキャッシュ、404と接続/503エラーの区別、入力取得前の失敗、選択結果の利用を自動テストした。

Pythonテスト74件成功。既存のNumPy/netCDF互換性警告1件は継続している。

MSMの2026-09-08 03 UTC初期値の気圧面/地表面と、GFS 00 UTC初期値f009の索引/本体はHEADで200を確認した。これは確認時点の公開状況であり、15:52当時の配信状態を復元したという意味ではない。シミュレーションやGRIB本体取得は実施していない。

## 次の時間帯のおすすめ

手元の学校CSVは2026-09-01 00:01〜09-04 23:40 JSTを含む。まず既存観測がある次の窓を推奨する（JST）。

|優先|開始〜終了|比較する挙動|
|---|---|---|
|1|09-03 18:00〜09-04 02:00|夕方から夜間の気温低下、都市の蓄熱・放熱|
|2|09-04 04:00〜12:00|明け方から午前の昇温と湿度変化|
|3|09-02 09:00〜17:00|別日の昼間、気温ピークと乾燥偏差|

検証目的からの提案であり、各日の晴雨をこの選定で認定したものではない。最高気温は14〜15時頃が多いが天気や風で変わるため、日中試験でも時系列全体を比較する（[気象庁の説明](https://www.jma.go.jp/jma/kids/kids/faq/b1_07.html)）。9月8日の事例を学校と比較する場合は、その日の学校CSVを追加する必要がある。

効果判定には同じ日時・観測で `msm_guided_solar.yaml` と `msm_guided_urban.yaml` を比較する。異なる日時のRMSEだけで設定の優劣を決めない。既定テンプレートは都市設定へ自動変更していない。

実行例（この修正作業では実行していない）：

```sh
./scripts/run_weather_case.sh \
  "2026-09-03 18:00" "2026-09-04 02:00" \
  --spinup-hours 6 --processes 4 \
  --template config/msm_guided_urban.yaml \
  --case-name case_20260903T1800_20260904T0200_urban
```
