# 2026-09-08 太陽角補間の再評価と都市面の見直し

## データと物理設定の変更

UCARが[WPS公式配布ページ](https://www2.mmm.ucar.edu/wrf/users/download/get_sources_wps_geog.html)で都市物理用に提供する `urbfrac_gaia2020_30s` を取得した。配布アーカイブは約30 MB、展開後約1.87 GB、2020年・30秒格子のデータ。配布ファイルのindexによれば値は不透水面率0〜1で、WRFのFRC_URB2Dへ入力される。アーカイブとindexのSHA-256、ファイル一覧・サイズ・出典・参照年を `data/geographic/optional/urbfrac_gaia2020_30s/provenance.json` に保存する。

[WRF公式の都市物理説明](https://www2.mmm.ucar.edu/wrf/site/documentation/users_guide/physics.html)に基づき、Noahに単層都市キャノピー（SLUCM）を組み合わせる。ローカル `phys/module_sf_noahdrv.F` でも、都市率に応じて都市面と自然面のHFX/LH等を合成する処理を確認した。観測温度に合わせた定数補正や地表値の上書きはしない。

```yaml
# config/msm_guided_urban.yaml の追加設定
wrf:
  urban_physics: 1
  urban_fraction_source: gaia2020
```

生成namelistは `sf_urban_physics = 1, 1, 1,`。太陽角補間1、YSU、Noah、Thompson、RRTMG、ナッジングgq=1e−5、9/3/1 km、45層、54/18/6秒、6時間spin-up、出力間隔はsolar対照から維持する。既定の `config/msm_guided.yaml` は変更しない。大きな物理変更なので候補の精度は完走して評価するまで未検証。

既存 `WPS_GEOG` には追加しない。`WPS_GEOG_urban_gaia2020` で既存データへのリンクと追加データを組み合わせ、既定実験が自動的に変わらないようにした。全metgridファイルで都市率の存在・フラグ・有限性・0〜1を検査。都市なのに率0のセルはWRFの標準値へのフォールバック対象なので件数を記録し、解析中心がこの状態なら起動を拒否する。

建物形状や材料はSLUCMの標準パラメータであり、東京を実測して設定したものではない。2020年の被覆率と2026年の現況との差も残る。追加の人工排熱・灌漑は標準表で無効（AHOPTION=0、IRI_SCHEME=0）を確認。都市カテゴリそのものを高解像度地図へ置換したわけではない。新しいキャノピー計算は計算量・状態変数を増やし、速度は悪化する可能性があるが、今回は物理改善を優先する。

別データとして[JAXAの日本域10 m土地利用土地被覆図 v25.04](https://www.eorc.jaxa.jp/ALOS/jp/dataset/lulc/lulc_v2504_j.htm)も調べた。2024/2022/2020年の地図があり、分類・集約・WRFカテゴリ対応の検証が必要。取得にはユーザー登録が必要なので今回は導入していない。現時点で直接使用可能な公式WPS形式のGAIAを先に採用した。大気初期・境界値はMSM、土壌補完はGFSを維持し、都市面変更との原因切り分けを優先する。

## 処理速度と精度不変の検証

`scripts/benchmark_mpi.py` は既存WRF入力を独立コピーし、30分のモデル時間で自然終了する試行を作る。物理設定・dtは変えず、全3領域の10分出力と全変数を比較する。開始・終了日の跨ぎ、微小差の検出も単体テストに含めた。短時間試行の一致は14時間の予報一致を保証しない。

今回の初回試行は2つのThompson表を再生成したため、実時間にはその初期化も含む。各試行は同条件だが、積分部分の時間も別に比較する。スクリプトはその後、既存表3つの正式ファイル名を使ってコピーするよう修正した。プロセスを途中停止して測定時間を作ってはいない。

Fortranの主要ソースは既に-O2、ベクトル化・ループ展開を使っていた。設定キャッシュの共通FLAGS欄だけを見て「無最適化」と判断しない。今回は再ビルド、fast-math、精度桁数変更、時間刻みの拡大は行っていない。

雲の後処理は、雲水・雲氷積算に使わないRHを計算せず、低・中・上層の範囲外で必ず寄与ゼロとなる層だけをループから省く。層間の晴天の切れ目、欠測伝播、対象層がない場合のNaNは維持する。元の全鉛直層は積算に使い、表示の間引きやfloat32化の追加で速くするものではない。

## 完走後の採否

1. 最新solarを対照とし、同じ観測・高度メタデータ・対象時刻でBias/MAE/RMSE/Nを比較する。都市物理とデータは一組の変更なので、個別効果の断定はしない。
2. 気温だけでなくRH・露点・風速・現地気圧・区間雨量を一緒に評価。時系列と昼夜差、学校と府中の両方を見る。
3. FRC_URB2D、都市/自然面、HFX/LH/TSK、雲・日射の変化を追跡し、土地利用変更が温度と水蒸気へどう影響したかを調べる。
4. 全領域監査を再実行。重大な不安定性や他変数の悪化があれば既定へ昇格させない。別日の検証を通るまで汎用的な改善とは扱わない。
5. WRF実時間、積分時間、前処理、後処理を分けて報告する。MPI変更は短時間の一致に加えて長時間・同物理の比較が必要。
