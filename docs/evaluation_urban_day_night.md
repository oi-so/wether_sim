# 昼間の都市モデルと夜間事例の評価（2026-09-08）

昼間の都市モデルで気温・湿度の誤差が大きく減った。一方、夜間には観測されていない雨を大量に予測した。**夜間ケースは従来の設定で実行されており、都市モデルの別時刻検証にはなっていない。** 今回は保存済み結果の解析だけを行い、WRF/WPSの再実行・物理設定変更は行っていない。

`case.json` と実際の `wrf_run/namelist.input` を照合した。3条件とも9/3/1 km、45層、親時間刻み54秒、6時間spin-up＋8時間評価、4 MPI、gq=1e−5 s⁻¹。微物理はThompson（8）、積雲はd01のみ有効（1,0,0）。昼間の対照には、水蒸気係数を変えたold_4ではなく、直前のsolar結果old_5を使った。

両地点をd03の最寄り格子で比較し、spin-upを除外。同時刻49点、学校の10分雨量は昼48・夜47区間。学校積算計の日付リセット・欠測境界は除外し、雨量合計も比較可能な区間だけで計算した。府中雨量は10分区間49点（開始時刻の値は直前10分を含む）。学校気圧は申告されたセンサー標高98.5 mに静力学換算した値を主指標とし、生値も保存した。気温・湿度・風の建物影響や観測高度差は補正していない。

昼間の旧・新結果は今回の同じ観測CSV・高度メタデータで再評価した。49点には時間相関があるため、独立49事例の検証ではない。

- 比較区間の雨量は学校1.09／観測1.99 mm、府中1.32／観測2.00 mm。雨量不足が残る。

**雨量は比較可能な区間で学校34.33 mm、府中27.96 mmに対し、観測はいずれも0 mm。** 学校の最大10分雨量は9/4 00:50に7.68 mm、府中は9/3 23:50に4.19 mm。両地点で大きな空振りとなった。学校の瞬間雨量も対象期間0であり、積算のリセットだけによる見かけの差ではない。

学校では露点Bias＋1.79℃、RHの水蒸気由来誤差成分＋8.30ポイントで、地表付近の過湿がある。ただしこれだけで上空の降水生成の原因は特定できない。府中はRH Biasがほぼ0でもMAE6.37ポイントで、時刻ごとの誤差が相殺されている。

気温は開始18時に学校＋2.69℃・府中＋2.79℃の高温。府中では0時にモデル23.88℃／観測25.2℃と逆に低温となり、夜間の観測変化を捉えていない。風も府中1:30にモデル3.50／観測0.7 m/sとなる。気温・風・降水の変化の時刻を合わせて診断する必要がある。

入力選択記録ではMSMは9/3 03 UTC初期値のFH0〜15、GFSは9/3 00 UTC初期値のFH3〜18。未来初期値の使用や途中のサイクル切替はなく、前回の404とは異なる問題である。MSM自体の降水・水蒸気・風の予測誤差とWRF内での誤差増幅の切り分けは未実施。都市モデルは無効なので、この空振りを都市モデル導入の副作用とは判断できない。

## 数値安定性・速度

両ケースともWRF SUCCESS。CFL/FATAL/NaNのログ検出0。各ケースのd01/d02/d03保存15/15/85時刻・全格子を監査し、非有限値、非正層厚、圧力の鉛直逆転、積算雨量の減少は検出されなかった。

d01では微小な負値が残る。昼間QCLOUD最小−4.87e−8、QRAIN−3.69e−8 kg/kg、RAINC−1.69e−8 mm。夜間QCLOUD−6.45e−7、QRAIN−8.97e−9 kg/kg。d02/d03は検査範囲の指摘なし。負値の原因は未特定で、元データはクリップしていない。`audit-case` の終了コード1はこれらの指摘によるもので、WRF異常終了ではない。保存間隔より短い振動はこの監査では判定できない。

都市化は対照より3.85分（6.5%）長い。今回は気温・湿度の改善と引き換えに計算時間が少し増加した。各1回の実測で、端末負荷や熱状態の影響を分離していない。夜は設定・気象が違うため高速化の根拠にはしない。WRF実時間はWPS・入力取得・動画生成を含まない（昼は動画なし、夜は動画あり）。メモリのピーク計測はない。

## 次の検証の優先順位

1. **高：夜間降水の原因を切り分ける。** 同じ入力を用いたMSMの降水・水蒸気・風、WRF各領域の雨量・上昇流・雲を比較し、広域入力の誤差か局地的増幅かを調べる。可能なら周辺アメダスやレーダーも用い、雨域の位置ずれと発生そのものの誤りを区別する。
2. **高：都市モデルを同じ夜間で比較する。** 今回の夜間を旧設定対照として残し、都市候補を別ケース名で実行する。実行時に `--template config/msm_guided_urban.yaml` の明示が必要。都市だけの効果を厳密に分けるなら夜間solar対照も必要（今回の夜は短波補間も0で、spin-upと夕方には日射がある）。本評価では実行していない。
3. **中：昼の開始時高温と府中の乾燥を調べる。** spin-up中の熱・水収支、MSMとの差、雲・日射の変化の時刻を確認する。気温・RH・露点・風・雨を同時評価し、RHだけに合わせた水蒸気nudging強化を避ける。
4. **中：微小負値を追跡する。** 発生格子・層・物理過程を特定する。値を切り上げて監査だけを通す変更は行わない。
5. **低：速度。** 同一期間・入力・設定で複数回測り、まず前後処理を対象にする。格子や時間刻みを粗くする必要性を示す結果ではない。

次の比較でも同じ観測区間のBias/MAE/RMSE/N、雨量合計・最大10分量・発生時刻を残す。今回のように観測が無降水の場合、観測降雨数を分母とする見逃し率は定義できないため、空振り区間数と過剰雨量を重視する。昼の1事例に調整を合わせ切らず、今回の夜や別の朝を独立検証に使う。既定テンプレートは変更していない。
