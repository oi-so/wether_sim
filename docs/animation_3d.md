## 開き方と操作

HTMLをWebGL対応ブラウザーで開く。地図画像と気象データは埋め込み済みで、閲覧時のサーバー・CDN・外部通信は不要（出典リンクをクリックした場合を除く）。スマホではJavaScriptを実行できるブラウザーを使う。

| 操作 | 動作 |
|---|---|
| マウス／指1本ドラッグ | 回転。真横・真下・上下反転を含め、仰角制限なし |
| Shift＋ドラッグ、右／中ボタンドラッグ | 視点の中心を画面方向へ移動 |
| 「ドラッグで中心移動」を選んでドラッグ | タッチ1本でも中心移動 |
| 指2本の移動・ピンチ | 中心移動と拡大縮小 |
| ホイール | 拡大縮小 |
| 矢印キー | 3Dは回転、2Dは移動 |
| Shift＋矢印キー、＋／− | 中心移動、拡大縮小 |
| 「2D 地表シミュレーション」 | 真上からの地表表示へ切替。ドラッグは移動になる |
| 3Dに戻す | 切り替える前の3D視点を復元 |
| 「滑らかな連続メッシュ」／「元の格子点」 | 接続面と点を切替 |
| 下限／上限高度 | 3Dの海抜高度帯を指定 |
| 高さの強調 | 1〜20倍。値・高度データは変わらない |
| 視点を戻す | 回転・中心位置・拡大率をリセット |
| マウスを合わせる／タップ | 近傍の表示格子の値と位置を表示（補間面そのものの値ではない） |

地形はWRFのHGTを連続した三角形で接続する。地理院タイルをWeb Mercator座標から各格子の緯度経度に対応付けて貼る。地域の広さに合わせて地図の細かさを選び、HTML用画像は最大2048×2048画素。地図画像の細かさは地形の標高解像度を高めない。出典：[国土地理院・地理院タイル](https://maps.gsi.go.jp/development/ichiran.html)。

上空の面は間引いた各モデル層の格子を三角形で接続し、色に使う値を面内で線形補間する。雲の物理的な等値面や体積の光線積分ではない。透明な面は奥から描き、地形との前後関係を深度で判定する。風は東西・南北・鉛直の瞬間ベクトルを矢印表示し、流跡線ではない。座標は中心付近の局所東西・南北距離による近似である。

## 地表の全項目と配色

HTMLの2Dモードと動画は同じ13項目を使用する。

- 気温、風速・風向、湿度、降水強度、区間降水量、地表気圧、地表面温度。
- 総雲量、下層・中層・上層雲量、雲水・雲氷鉛直積算量。

雲量は暗色から白へ変わり、白ほど多い。CLDFRA・QCLOUD・QICEも白が多い方向に統一した。雨は淡青・青・黄・橙・赤・紫の段階色で、区切りは1・5・10・20・30・50・80。降水強度ではmm/h、区間雨量ではmmの区分であり、両者の単位を区別する。80以上は最上位色。参考：[気象庁の雨雲の動き](https://www.jma.go.jp/bosai/rain/)。表示する値はWRF予測であり、レーダー観測ではない。

**既存の `precipitation_animation.mp4` は区間平均降水強度（mm/h）へ変更した。** 以前の区間雨量は `precipitation_interval_animation.mp4` に分離した。実際の時刻差で割るため、10分出力と約1時間出力を同じ強さとして比較できる。ゼロ以下の出力間隔・欠測は欠測のまま保持し、元の積算・区間雨量を変更しない。HTMLは無降水を透明にする。

## 作成コマンド

```bash
# 全3領域の動画・HTMLを新しい表示へ更新（既存可視化だけを上書き）
./scripts/animate_weather_case.sh output/case_20260904T1200_20260904T2000 --force

# HTMLだけ更新
./scripts/animate_weather_case.sh output/case_20260904T1200_20260904T2000 --dimension 3d --force

# 特定領域だけ、動画だけ
./scripts/animate_weather_case.sh CASE --domains d02 d01 --dimension 2d --force

# 地図タイルの取得ができない環境では地形・気象だけを出力
./scripts/animate_weather_case.sh CASE --no-basemap --force

# 大気表示を軽量化（2D地表は全格子のまま）
./scripts/animate_weather_case.sh CASE --dimension 3d --force \
  --horizontal-stride 5 --vertical-stride 3 --time-stride 2
```

初回の背景地図取得には国土地理院のタイルサービスへの通信が必要。`data/geographic/gsi_tiles/` のキャッシュを再利用する。HTMLは全範囲・全地表項目を含むため、今回のd03で約104.4 MiB、d02で約20.2 MiB、d01で約19.6 MiB。スマホで重い場合は時刻間引きや3D表示間引きを指定する。既定は水平3格子、鉛直2層、毎時刻で、最後の時刻も含む。表示上の間引き・補間はWRFの計算精度を変えない。

`--force` なしでは既存出力をスキップするため、旧版HTMLや旧配色の動画を更新するときは必須。`atmosphere_3d.json` にスケール・領域・サンプリング・地図ズーム・容量を保存する。新しいWRF実行も動画生成が有効なら全3領域を出力する。

## 気象量の定義

WRFの出力は摂動量とずれた格子を含むため、以下の変換を行う。[WRF公式の変数定義](https://www2.mmm.ucar.edu/wrf/users/wrf_users_guide/build/html/output.html)

- 気温：`(T + 300) × ((P + PB) / 100000)^(Rd/Cp) − 273.15`（℃）。Tをそのまま気温として扱わない。
- 高度：`(PH + PHB) / g` の上下界面平均（海抜km）。層厚は界面高度の差。
- 風：U、V、Wをそれぞれのずれた格子から隣接平均で質量格子へ変換し、U・VはCOSALPHA・SINALPHAで東西・南北へ回転。Wは上向きが正。風速は3成分の合成。
- 湿度：QVAPOR（混合比）から `e = r p / (0.622 + r)` で水蒸気圧を求め、液水に対する飽和水蒸気圧で割る。氷に対する相対湿度ではない。表示は0〜100%へ制限する。
- QCLOUD、QICE：乾燥空気に対する混合比をkg/kgからg/kgへ変換。CLDFRAは0〜1から%へ変換。

### 2D雲量

CLDFRAを鉛直に重ねる「最大ランダム重なり」の診断値。連続する雲層は最大重なり（最大の雲量）、雲のない層で離れた雲群はランダム重なり `1 − ∏(1 − 雲群の雲量)` とする。総雲量は全モデル層を対象とし、地表付近の霧も含める。

下層は地上300〜2000 m、中層は2000〜6000 m、上層は6000 m以上。区切りはWRF-Pythonの既定高度区分を参考にするが、同ライブラリのRHからの雲量推定とは異なり、保存されたCLDFRAを直接使う。該当するモデル層がない帯や欠測を含む帯は欠測とし、晴天0%と区別する。[高度区分の参考](https://wrf-python.readthedocs.io/en/develop/internal_api/generated/wrf.g_cloudfrac.get_cloudfrac.html)

これは重なりの仮定を伴う鉛直雲量であり、観測された総雲量や雲の光学的厚さそのものではない。雲量100%でも短波放射が0になることを意味しない。

### 雲水・雲氷の鉛直積算量

`Σ(混合比 × 乾燥空気密度 × 層厚)`（kg/m²）。乾燥空気密度は全圧・気温・水蒸気混合比から計算し、混合比の分母を一致させる。QCLOUDには雨水を、QICEには雪・霰を含めない。2Dの積算は全モデル層・全水平格子で行い、3D表示の間引きは適用しない。

## 検証と制約

- 79テスト成功。全78動画のH.264形式と49/9フレーム、全6HTMLの配列長・地図UV・相互リンクを確認した。動画フレームで日本語・配色・地図の表示を確認した。
- 単体テストは気象変換に加え、実際の出力間隔による雨量換算、地図UVの向きと範囲、全13項目・全領域の出力、親領域の終端時刻を検証する。
- Node.jsによるDOM/WebGLの模擬環境で、連続メッシュの頂点、気象要素切替、時刻変更、無制限回転、中心移動、二本指ピンチ・キャンセル、2D/3D視点復元を検証する。実GPU描画のテストではない。
- 実ブラウザーでのローカルHTML表示はブラウザー安全ポリシーに拒否されたため、今回の実ブラウザー画面確認・スマホ実機確認は未実施。WebGLのドライバー依存や巨大HTMLの読込速度には未確認部分がある。
- 雨や雲の配色変更は予測の改善ではない。夜間ケースに見られた過剰降水など、元のシミュレーションの誤差も表示される。
