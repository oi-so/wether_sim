## 3. 資料にない追加案と重要度

|重要度|問題・未解決点|今回の対応・修正案|
|---|---|---|
|高|水蒸気だけ改善して気温・府中風速を悪化させる|gq=5e−5を既定へ昇格せず、直前の1e−5を対照条件として維持する。|
|高|日射と地表熱収支の誤差候補|太陽高度に基づく短波補間 `swint_opt=1` を単独の感度実験にする。雲・都市面の寄与は別実験で切り分ける。|
|中|微小負の水成物|全領域監査を維持。輸送/微物理のどちらが原因か未確定のためWRFソースを根拠なく変更しない。|
|中|同一入力の感度実験でmetgridを毎回計算|実入力・設定・実行ファイルのSHA-256に基づくmetgridキャッシュを実装。復元後も全領域・全時刻の物理範囲検査を行う。|
|中|1事例だけでは汎化精度を判断できない|今回の実験完走後に同一観測で比較し、別日の検証を通るまで既定にしない。|

UCARの[WRF推奨設定](https://www2.mmm.ucar.edu/wrf/users/namelist_best_prac_wrf.html)は、放射計算間隔10〜15分を使う際にswint_optによる短波補間を案内している。[namelist公式説明](https://www2.mmm.ucar.edu/wrf/users/wrf_users_guide/build/html/namelist_variables.html)では1は太陽天頂角に基づく補間である。ローカルWRF 4.8のRegistryと `phys/module_radiation_driver.F` も確認し、最新実行のSWINT_OPT=0を確認した。

学校の期間平均SWDOWNは直前193.86→最新245.61 W/m²、HFXは126.09→154.14 W/m²、TSKは304.59→305.73 K。水蒸気を増やすだけで地表の過熱が改善するとは限らない。これは放射・地表熱収支を調べる根拠だが、日射観測がないので放射誤差の因果確定ではない。

`swint_opt=1` は放射呼出し間の太陽角の変化を扱う。**雲の変化を各力学ステップで再計算するものではなく、暖偏差の減少は未保証。** [WRF放射の説明](https://www2.mmm.ucar.edu/wrf/site/users_guide/physics.html)を踏まえ、雲の時間変化については後続のradt感度実験が必要になり得る。今回はradtを15分のまま保ち、太陽角補間だけを変える。

[WPS公式説明](https://www2.mmm.ucar.edu/wrf/users/wrf_users_guide/build/html/wps.html)にある通り、metgridの水平補間結果はrealへの入力である。同じ日時・領域のWRF物理感度実験で再利用できる。地理データだけの再利用と異なり、気象中間ファイルも一致する場合だけ有効にする。

## 4. 実装・検証

### 精度候補

`WRFConfig.shortwave_interpolation` とnamelistへの出力を追加した。既定は0のまま、未検証の候補 `config/msm_guided_solar.yaml` だけ1にする。

```yaml
wrf:
  nudging_moisture_s: 0.00001
  shortwave_interpolation: 1
```

生成するnamelistの差は次の1行だけ（比較対象は `config/msm_guided.yaml`）。

```fortran
 swint_opt = 1,
```

単体テストで設定全体とnamelist全体を比較し、このオプション以外の同一性を確認した。最新のgq=5e−5ケースとの比較ではgqも異なるので、**単独の効果判定には `output/old_3` を使う**。9/3/1 km、45層、54/18/6秒の時間刻み、6時間spin-up、4 MPI、出力間隔を維持。丸め精度の変更、fast-math、時間刻み拡大は行わない。

### 精度を変えない前処理高速化

新しい `simulation/metgrid_cache.py` を `_prepare_wps` に組み込んだ。

```python
signature = input_signature(inputs)  # namelist, table, executable, geo_em, MSM, GFS
restored = restore_metgrid(cache_root, signature, directory, names)
if not restored:
    # 通常のmetgrid実行
    ...
_validate_metgrid_inputs(directory, config)  # 復元時も省略しない
```

`data/cache/metgrid/` へmanifestと独立コピーを保存。ハードリンクを使わず、全出力のチェックサムが一致してから復元する。破損・不足・入力変更は通常計算へ戻る。既存出力の上書きを拒否する。`--no-metgrid-cache` で再利用と登録を無効化でき、各ケース `wps/metgrid_cache.json` に使用状況を残す。

最新実データで18ファイル（68.64 MB）のチェックサム完全一致と全入力物理検査を確認した。入力1.629 GBのハッシュ計算0.768秒、検査・復元0.059秒、初回登録0.057秒。metgrid本計算41.59秒に対し、再利用経路はこの測定で約0.83秒（物理範囲検査は両経路共通）。同じ入力で繰り返す場合の約40秒短縮であり、**WRF積分を40秒化するものでも、全工程を大幅短縮した実証でもない**。キャッシュ容量は条件ごと約69 MB増える。新しい日時では計算を省略できない。

動的共有ライブラリや実行環境全体のハッシュは含まれない。WPS依存ライブラリを入れ替えた後の検証では `--no-metgrid-cache` を使い、旧キャッシュを再利用しない。バイナリ自体の変更は自動検出する。破損した既存エントリは書き換えず、再計算へ戻る。

Pythonテスト55件成功（既存のNumPy/netCDF互換性警告1件）。入力変更による無効化、出力破損、独立コピー、上書き防止、候補設定の単一差分を検証。WRFの予測精度改善は、これらの単体テストだけでは実証できない。

### 完走後の精度・速度判定

1. `audit-case` でCFL/FATAL、NaN、圧力・層厚、負混合比、雨量リセットを再確認する。
2. 同一時刻・同一観測・同一高度メタデータでBias/MAE/RMSE/Nを比較。温度、RH、露点、風速、気圧、区間降水を一緒に判定し、湿度だけで採用しない。降水は10分量と比較可能区間の合計、イベント時刻も調べる。
3. 直前gq=1e−5を対照に、日中/夜間の誤差とSWDOWN/HFX/LH/TSK、雲の対応を比較する。日射・雲観測がない場合は因果を断定しない。
4. 高速化は `--no-metgrid-cache` とのmet_em完全一致を主検証にする。同じWRF設定・MPIでWRF入力も一致することを確認すれば、前処理に由来する精度変化を切り分けられる。物理候補とキャッシュの効果を混同しない。
5. WRF実時間と前処理時間を別に記録する。反復速度測定は同等の負荷・冷却条件で行う。時系列の自己相関を考慮し、複数独立日または日単位の再標本化で誤差差の不確実性を評価する。
