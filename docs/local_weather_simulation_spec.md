# 局地気象シミュレーション 仕様書

## 1. 概要

本システムは、指定した地点を中心として局地的な気象シミュレーションを行い、気温・湿度・風・降水などの時間変化を予測・再現することを目的とする。

特に、中心地点から半径約20 kmの範囲を主な解析対象とし、WRF（Weather Research and Forecasting Model）を用いて高解像度のシミュレーションを行う。

また、過去日時を指定した再現実験（hindcast）にも対応し、アメダスおよび本校の観測装置による実測値と比較することで、シミュレーションの精度を評価できるようにする。

シミュレーション結果は数値・グラフだけでなく、地図上のアニメーションとして可視化する。

---

## 2. 目的

### 2.1 主目的

- 指定地点周辺の局地的な気象を高解像度でシミュレーションする。
- 中心地点から半径約20 kmの範囲について詳細な解析を行う。
- 過去の日時を指定し、実際の観測結果と比較できるようにする。
- 将来的には現在時刻以降の局地予測にも利用できる構成とする。

### 2.2 研究上の目的

- WRFの水平解像度によって局地気象の再現性がどのように変化するか調べる。
- アメダス観測値とシミュレーション結果を比較する。
- 本校の観測装置による気温などのデータと比較する。
- アメダスと本校で観測される気温差などの原因を、地形・土地利用・風・地表面状態などから考察する。
- 将来的には観測データをデータ同化した場合の精度改善について調べる。

---

## 3. シミュレーション領域

局地的な気象は対象範囲外の大気の影響を受けるため、半径20 kmのみを単独で計算せず、複数の計算領域をネスティングする。

### 3.1 Version 1

| Domain | 水平解像度 | 計算範囲の目安 | 主な役割 |
|---|---:|---:|---|
| d01 | 9 km | 約900 × 900 km | 大規模な気圧配置・風などを表現 |
| d02 | 3 km | 約300 × 300 km | 地方・関東規模の気象を表現 |
| d03 | 1 km | 約100 × 100 km | 対象地点周辺の局地気象を表現 |

親領域と子領域の格子間隔比は原則として 3:1 とする。

### 3.2 主解析領域

d03の中心地点から

- 半径約20 km

を主解析領域とする。

d03自体は境界の影響を減らすため、解析対象より十分広い約100 km四方とする。

### 3.3 将来拡張

必要に応じて以下の高解像度領域を追加する。

| Domain | 水平解像度 | 計算範囲の例 |
|---|---:|---:|
| d04 | 約333 m | 約40～60 km四方 |

ただし、格子間隔を細かくしただけでは精度向上が保証されないため、1 kmモデルとの比較を行った上で追加する。

## 4. 日時指定

### 4.1 基本仕様

ユーザーが以下を指定できるようにする。

- シミュレーション対象日時
- シミュレーション開始日時
- シミュレーション終了日時
- タイムゾーン
- spin-up時間

基本タイムゾーンは `Asia/Tokyo` とし、内部計算では必要に応じてUTCへ変換する。

### 4.2 過去再現

過去の日時を指定してシミュレーションできるようにする。

用途：

- 実際に発生した気象現象の再現
- アメダスとの比較
- 本校観測装置との比較
- モデル設定の評価
- 解像度による精度差の評価

### 4.3 将来予測

取得可能な初期値・境界値データが存在する場合、現在以降の日時についてもシミュレーションを実行できる設計とする。

Version 1では過去再現を優先し、安定して実行できるようになった後にリアルタイム・将来予測を追加する。

## 5. 入力データ

### 5.1 大気初期値・境界値

WRFを実行するためには、地表だけでなく上空を含む3次元の大気状態が必要である。

そのため、アメダスだけをWRFの初期値として使用することはせず、数値予報・解析データを使用する。

候補：

- 気象庁 MSM
- その他、WRFで利用可能な解析・予報データ

必要となる主な要素：

- 気温
- 気圧
- 水蒸気量・湿度
- 東西風
- 南北風
- 地表面気圧
- 地表面温度
- その他WRFの初期化に必要な変数

---

## 6. 地理・地表データ

局地シミュレーションでは地形や土地利用が大きな影響を与えるため、WPSを用いて地理データを入力する。

主なデータ：

- 標高
- 土地利用
- 植生
- 土壌
- 海・湖などの水面

将来的には、より高解像度な地形・土地利用データへの置き換えも検討する。

## 7. アメダスデータ

### 7.1 用途

アメダス観測値は主に以下に使用する。

1. シミュレーション結果の検証
2. MSM等との比較
3. 将来的なデータ同化

### 7.2 使用する観測要素

取得可能な地点について、主に以下を利用する。

- 気温
- 相対湿度
- 風向
- 風速
- 降水量
- 気圧
- 日照・日射関連データ

### 7.3 データ取得

過去実験では、指定期間のアメダスデータを取得し、共通の時刻形式・単位へ変換して保存する。

例：

```text
data/
└── observations/
    └── amedas/
```

## 8. 本校観測装置のデータ

### 8.1 目的

本校で計測している気象データを、シミュレーション精度を評価する独立した観測データとして利用する。

特に、本校と周辺アメダスとの気温差をシミュレーションがどの程度再現できるか調べる。

### 8.2 対象データ

観測装置で取得可能な項目から利用する。

最低限：

- 気温

取得できる場合：

- 湿度
- 気圧
- 風向
- 風速
- 降水量
- その他の観測項目

### 8.3 必要なメタデータ

各観測装置について以下を保持する。

- 観測地点名
- 緯度
- 経度
- 標高
- 観測要素
- 観測間隔
- 使用センサー
- 欠測値の表現
- 時刻形式
- タイムゾーン

### 8.4 データ保存

```text
data/
└── observations/
    ├── amedas/
    └── school/
```

アメダスと本校観測データは共通の内部形式へ変換し、同じ評価処理を利用できるようにする。

## 9. spin-up

WRFの計算開始直後は、モデル内部の大気・雲・地表面などが十分に調整されていない可能性がある。

そのため、解析対象時刻より前からシミュレーションを開始する。

Version 1の標準設定：

- spin-up：12時間
- 解析時間：12時間程度

例：

```text
00:00  シミュレーション開始
   |
   | 12時間 spin-up
   |
12:00 解析開始
   |
   | 12時間
   |
24:00 解析終了
```

spin-up時間は設定ファイルから変更可能とする。

## 11. 数値解析

### 11.1 任意地点の時系列

例：

```text

```

### 11.2 観測地点への補間

アメダスおよび本校観測地点の緯度・経度から、WRF格子の値を補間して比較する。

最近傍格子だけでなく、将来的には双線形補間なども利用できるようにする。

## 12. 精度評価

観測値を

\[
O_i
\]

WRFの予測値を

\[
P_i
\]

とする。

### 12.1 Bias

\[
Bias = \frac{1}{N}\sum_{i=1}^{N}(P_i-O_i)
\]

モデルが平均的に高め・低めのどちらへ偏っているかを評価する。

### 12.2 MAE

\[
MAE = \frac{1}{N}\sum_{i=1}^{N}|P_i-O_i|
\]

平均的な誤差の大きさを評価する。

### 12.3 RMSE

\[
RMSE =
\sqrt{
\frac{1}{N}
\sum_{i=1}^{N}
(P_i-O_i)^2
}
\]

大きな誤差をより強く評価する。

### 12.4 比較対象

以下を可能な範囲で比較する。

- MSM
- WRF 3 km
- WRF 1 km
- アメダス
- 本校観測装置

## 13. 本校とアメダスの比較

本校の観測装置と周辺アメダスについて、

\[
\Delta T_{\mathrm{obs}}
=
T_{\mathrm{school}}
-
T_{\mathrm{AMeDAS}}
\]

を求める。

同様にシミュレーションから、

\[
\Delta T_{\mathrm{WRF}}
=
T_{\mathrm{WRF,school}}
-
T_{\mathrm{WRF,AMeDAS}}
\]

を求める。

これらを比較して、

- 本校とアメダスの気温差をWRFが再現できるか
- どのような気象条件で差が大きくなるか
- 土地利用・地形・風などと関連があるか

を解析する。

## 14. 可視化

### 14.1 静止画

指定した時刻について、地図上に以下を表示できるようにする。

- 気温分布
- 湿度分布
- 風速分布
- 風向・風ベクトル
- 降水量
- 気圧
- 地表面温度

必要に応じて以下を重ねる。

- 中心地点
- 半径20 kmの解析範囲
- アメダス地点
- 本校観測地点
- WRF各Domainの範囲

### 14.2 時系列グラフ

アメダス、本校観測装置、WRFについて時系列を比較する。

例：

```text
気温
 ^
 |       WRF
 |      /---
 |  ---/
 |-- 実測
 +-----------------> 時刻
```

### 14.3 アニメーション

シミュレーション結果を時間方向に連続表示する。

表示対象：

- 気温
- 湿度
- 風
- 降水
- 気圧
- その他選択した気象要素

基本機能：

- 再生
- 一時停止
- 先頭へ戻る
- 1フレーム進む
- 1フレーム戻る
- 再生速度変更
- 時刻表示
- カラーバー表示

風については、気象要素の色分布に加えて風ベクトルを重ねられるようにする。

### 14.4 アニメーション出力

以下の形式への出力を可能にする。

- MP4
- GIF

Version 1ではPythonによる生成を優先する。

候補ライブラリ：

- matplotlib
- xarray
- numpy
- ffmpeg

## 19. Version 2以降の候補

### 19.1 観測データ同化

アメダスやその他の観測値を初期場・計算中のモデルへ取り込む。

候補：

- OBSGRID
- observational nudging
- WRFDA

以下を比較する。

| 実験 | 解像度 | 観測データ同化 |
|---|---:|---|
| A | 3 km | なし |
| B | 1 km | なし |
| C | 1 km | あり |
| D | 約333 m | あり |

これにより、

- A → B：水平解像度を上げる効果
- B → C：観測データ同化の効果
- C → D：さらに高解像度化する効果

を分離して評価する。

### 19.2 約333 mモデル

1 kmモデルが安定して実行できた後、対象地域のみを約333 mまで細分化する。

### 19.3 リアルタイム予測

現在の最新気象データを自動取得し、現在以降のシミュレーションを実行する。

### 19.4 自動実行

将来的には、

```bash
uv run weather-sim run config.yaml
```

などのコマンドのみで、

1. データ取得
2. WPS
3. WRF
4. 解析
5. 評価
6. 可視化

まで自動実行できるようにする。

### 19.5 GUI / Web UI

必要に応じてGUIまたはWeb UIを追加し、

- 地点指定
- 日時指定
- 気象要素選択
- アニメーション再生
- 観測値比較
- 統計値表示

を視覚的に操作できるようにする。

## 20. 開発方針

最初から高解像度化・データ同化・GUIをすべて実装するのではなく、以下の順に進める。

1. WRFをMac上で実行する
2. 1つの過去事例を9 km単独で再現する
3. 9 km → 3 kmへネストする
4. 9 km → 3 km → 1 kmへネストする
5. Pythonからwrfoutを読み込む
6. 気温・風を可視化する
7. アニメーションを作成する
8. アメダスとの比較を実装する
9. 本校観測装置との比較を実装する
10. 複数事例で評価する
11. 必要に応じてデータ同化を導入する
12. 必要に応じて約333 mまで高解像度化する

最優先は、**「過去の1事例について、1 kmまでのWRFシミュレーションを正常に実行し、観測値との比較とアニメーション表示まで行う」こと**とする。
